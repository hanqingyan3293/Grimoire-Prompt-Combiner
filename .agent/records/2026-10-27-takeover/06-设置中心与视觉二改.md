# 06 设置中心与视觉二改

## 1. 设置的形态（用户 2026-10-27 定）

- 设置是一个**普通面板**，不是浮窗；默认在主窗口里占一整页标签（左侧分类栏 + 右侧分组卡片），可最大化。
- **双击面板标题 / 点按钮 → 独立成窗口**；独立前后自动保存与同步。
- 分类可折叠；搜索跨全部设置；常用/高级分层，默认只显示常用。
- 保留「在独立窗口打开」入口，但默认走主窗口整页。

### 机制事实（读源码得到）

| 事实 | 影响 |
|---|---|
| 独立窗口是**另一个渲染进程**，面板重新挂载后从共享工作区文档恢复 | 状态必须在 store/数据库，不能放组件内部 |
| 设置写入会向所有窗口广播 `data:refresh`（`settings.ipc.ts:71`） | 同步链路已存在，不需要新造 |
| 弹出窗口没有「背景色 + 就绪再显示」 | 会白闪一下，需修 |

### 防闪烁三措施

1. 窗口背景色取当前主题底色（深色模式不能先闪白）。
2. 内容就绪后再显示窗口。
3. 原窗口先保留占位块，等新窗口就绪再移除，避免布局跳变。

### 面板状态契约（要补的基础设施）

每个面板声明三件事：能否独立、独立前如何保存草稿、回来如何恢复。否则「一半面板拖出去就丢状态」。

## 2. 主题：沿用现有系统

- 昼夜两套 + 色轮自定义主色（自动算深浅阶），已有实现。
- 需要新增**主题桥**：把我们的变量翻译成 Cherry 的变量族，并同步深色开关。

| 我们的变量 | Cherry 的变量 |
|---|---|
| --color-bg-primary | --color-background |
| --color-bg-secondary | --color-card |
| --color-bg-tertiary | --color-muted |
| --color-text-primary | --color-foreground |
| --color-text-secondary | --color-muted-foreground |
| --color-border | --color-border |
| --color-accent | --color-brand-500 + --color-accent |
| 主色深浅阶 | --color-brand-50 … 950 |
| 深色模式 | 在 html 上添加 dark 类 |

同步方式：主进程在主题变化时广播，Cherry 窗口收到后设置变量与类名。

## 3. 二改的 8 层（顺序即优先级）

| 层 | 改什么 | 为什么 |
|---|---|---|
| 1 设计令牌 | 颜色/圆角/间距/阴影/字号/动效统一成变量 | 一处改、全局生效 |
| 2 品牌 | 产品名、图标、关于页、窗口标题、空状态、启动画面 | 最直观的「不像 Cherry」 |
| 3 密度 | 行高、卡片内边距、表格密度 | Cherry 偏松，我们信息量大 |
| 4 组件 | 按钮/开关/标签/对话框/表格 | 统一手感 |
| 5 布局 | 左侧栏结构、导航语义、页头、面包屑 | 按我们的信息架构重排 |
| 6 图标 | 统一图标族与线宽 | 禁止两套混用 |
| 7 文案 | 术语统一（提示词/标签/素材/作品/版本/会话/智能体） | 一致性 |
| 8 动效 | 统一时长与缓动 | 禁止逐页自定义 |

**判断**：颜色只占三成，密度/布局/品牌/文案占七成。只换色，内行仍能认出是 Cherry。

## 4. 顺序与红线

- 先令牌 + 品牌，再做新界面（否则新页面按旧风格做完还要返工）。
- **不修改 `src/vendor/cherry/source`**；所有改造在 compat 层、主题层、包裹层完成。
- 一次只改一层，可单层回退。
- 二改期间不做新功能，避免分不清「改坏了」还是「本来没接」。
