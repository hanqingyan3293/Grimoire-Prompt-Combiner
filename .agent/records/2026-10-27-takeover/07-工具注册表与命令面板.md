# 07 工具注册表与命令面板

## 1. 用户的诉求

「我们的软件功能很多，想把很多东西做成工具，方便内置 Agent 调用，方便控制软件，尽量减少不必要的 token。」

## 2. 判断：方向对，但要加五条规矩

成本真相：每个工具的**名字 + 描述 + 参数结构**都会进模型上下文。30 个工具按每个 70–90 个标记估算，每轮约 2000+ 标记，比很多对话正文更贵。所以「工具越多越省」不成立。

| # | 规矩 | 说明 |
|---|---|---|
| 1 | 按域分组、按需装载 | 提示词/标签/图片/画布/工作区/设置/MCP/任务 八组；聊天页只装提示词+标签（8–10 个），Agent 页装全量；单轮开销可压到 600 左右 |
| 2 | 一个工具 = 用户会说的一句话 | 「把当前提示词存成素材」是一个工具，不是创建/加标签/绑图三个 |
| 3 | 只回摘要 + 句柄 | 查图返回「20 张 + 编号」，绝不回图片本体；大结果分页，默认 20 条 |
| 4 | 写操作两段式 | 先预演（会改什么），再执行；删除/执行命令/改设置/批量必须确认 |
| 5 | 命令面板与 Agent 共用同一注册表 | 人点按钮 = Agent 调工具 = 同一实现，避免两份维护 |

补充：工具描述用中文写（模型读中文没问题），工具名保持稳定短标识；危险工具靠权限策略而不是提示词。

## 3. 已有骨架

`src/main/ai/runtime/grimoire-tools.ts`、工具注册表、权限策略、能力账本都已存在。缺的是「按域分组装载」与「预演/执行两段式」。

## 4. 命令面板

参考 Cherry 的快捷面板（截图 0072），做我们自己的：一个键唤出、可搜索、回车执行；列表来自同一份工具注册表，按域分组显示。
