# 09 开发原则与验收

## 1. 先框架后填充（用户明确要求）

> 宁可先把框架搭好、让他能看见，再一点点填充；不要做简易版 UI 或简易版功能。

落地方式：

1. 新功能第一步：**挂真实页面/真实结构**（可以是只读、可以明确标「未接线」）。
2. 第二步：接数据。
3. 第三步：接动作。
4. 每步都在界面上可见，不允许「看起来有、其实没有」。

## 2. 未接线的统一呈现

- 统一灰色角标 + 悬停说明缺什么；
- 不允许安静地什么都不做；
- 不允许用空列表/成功状态掩盖失败。

## 3. 不修改只读源

- `src/vendor/*/source` 只读；所有适配在 compat / integrations / 主题层完成。

## 4. 三门禁

每个里程碑必须过：自动化（类型/测试/构建）、功能（真实冒烟）、迁移审计（对照矩阵）。

## 5. 状态词汇

只用：DIRECTLY_MIGRATED / VENDORED / WRAPPED / ADAPTED / MINIMAL_MODIFICATION / PARTIALLY_MIGRATED / BLOCKED / MISSING / REIMPLEMENTED / NOT_IMPLEMENTED。

不报「基本完成」「核心完成」「类似实现」；每个未完成项必须写缺什么、下一步是什么。

## 6. 版本控制

- 不 push、不建 Release；
- 每个里程碑本地提交一次；
- 最终门禁通过前不建「完成提交」。

## 7. 与旧文档的关系

旧账本（STATUS 等）只作历史引用，不得当现状。现状只看 `../STATE.md`。
