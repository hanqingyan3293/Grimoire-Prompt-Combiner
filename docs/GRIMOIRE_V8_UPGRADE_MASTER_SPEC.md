## 2. 产品方向（已锁定）

### 2.1 定位与用户

魔导书升级版是开源、本地优先、面向 Windows 的 AI 绘画创作工作台。它以提示词资产为核心，把图片反推、提示词组织、ComfyUI 生成、生成历史、素材管理和无限画布串成完整闭环。

采用分层用户模型：

- 普通用户看到合理默认值和渐进展示的功能，可快速完成反推与生成。
- 专业用户可使用完整参数、动态工作区、工作流映射、批处理和无限画布。
- 简化模式只能降低首屏复杂度，不能删除底层完整能力。

### 2.2 项目性质与平台

- 开源桌面工具，当前许可证基线 GPL-3.0。
- P0 平台：Windows 10/11 x64。
- 数据和主要能力默认在本机运行与保存。
- 当前阶段不建设自有云服务。

### 2.3 首版成功标准

首个升级版必须完成可复现闭环：

    导入图片
      -> WD14 或现有 AI 识图反推
      -> 编辑、组合和收藏提示词
      -> 选择快捷参数或导入 ComfyUI API 工作流
      -> 提交生成任务并显示队列、进度和错误
      -> 保存结果、参数、种子、模型和工作流
      -> 放入项目、历史、资产库或无限画布继续创作

同时，所有原有关键功能和 Blender 式动态工作区必须继续可用。

### 2.4 当前阶段明确不做

- 账户、云同步、多人实时协作。
- 支付与商业订阅。
- 应用内模型训练。
- 对外插件市场。
- 自行重做 ComfyUI 节点编辑器。

## 3. 主题与 UI/UX（已锁定）

### 3.1 双轴主题系统

现有 7 种配色来自同一个色轮自定义体系，并非 7 套独立视觉设计。升级版结构为：

    外观模式（浅色 / 深色 / 跟随系统）
      ×
    主题色（7 个内置色轮预设 / 用户自定义色轮颜色）

规则：

- 默认可跟随系统，用户手动选择后记住偏好。
- 7 个内置配色全部保留，继续支持色轮自定义。
- 主题色只是种子色，用于派生主要操作、悬停、选中、焦点和弱背景色。
- 背景、正文、边框、成功、警告和危险使用语义色，不等同于主题色。
- 自定义色可读性不足时自动校正控件和文字派生色。
- 浅色、深色分别设计和测试，禁止简单反相。
- 图片查看和无限画布可使用独立中性工作背景。

### 3.2 视觉与交互

- 安静、专业、内容优先，符合生产力桌面工具。
- 不做营销页式布局，不用大面积装饰卡片、夸张圆角和无功能渐变。
- 卡片仅用于独立对象、模态框和确需边界的工具，圆角原则上不超过 8px。
- 页面区块不使用卡片嵌套卡片。
- 统一使用 Lucide 图标，不用 Emoji 作为结构图标。
- 图标、按钮命中区、悬停、按下、禁用、焦点状态统一。
- 字体、字号、字重、行高、间距、阴影、层级和动画全部 Token 化。
- 动画表达状态变化，常规 150-300ms，支持减少动画。
- 普通模式渐进展示参数，专业模式开放全部控制。

### 3.3 无障碍与显示适配

- 目标为 WCAG 2.2 AA 关键要求。
- 普通正文对比度不低于 4.5:1，大型文字和关键图形不低于 3:1。
- 键盘可访问主要功能，焦点顺序符合视觉顺序。
- 图标按钮有可访问名称和工具提示。
- 状态不能只靠颜色表达。
- 拖拽有按钮、菜单或键盘替代。
- 支持文字缩放与减少动画，不得出现遮挡。
- 验证 1366x768、1920x1080、2560x1440。
- 验证 Windows 缩放 100%、125%、150%、200%。
- 应用最小窗口 1024x700。

### 3.4 页面状态

所有核心界面必须有空、加载、成功、错误、离线、禁用、处理中、部分完成、可重试和不可重试状态。

## 6. 参考项目审计结论

### 6.1 infinite-canvas

- MIT，React 19、Zustand、Tailwind 4，与主工程接近。
- 已有节点、连线、小地图、撤销重做、导入导出和插件 SDK。
- 上游处于开发期，明确不保证历史数据兼容。
- 固定具体提交，维护魔导书内部分支。
- 复用核心交互和合适的节点 SDK。
- 不把完整独立 Web 应用原样嵌入 Electron。
- 替换其 IndexedDB 数据真相、浏览器密钥、前端直连 API、独立路由和插件市场。
- 接入魔导书 SQLite、资源库、任务、主题和安全边界。
- 保留 MIT 声明和本地修改记录。

### 6.2 朋友“随孤”的项目

- Python/Flask + 原生 HTML/JS。
- wd14_tagger.py 使用 ONNX Runtime，支持 SmilingWolf WD14 系列、模型扫描/切换、CPU/CUDA。
- comfy_proxy.py 默认连接 http://127.0.0.1:8188。
- ComfyUI 是反向代理和工作流构造器，不修改 ComfyUI。
- 已验证 SDXL、Krea2、Anima，支持模型、LoRA、/prompt、/queue、/history 和结果图片。
- 可解析 A1111、Forge、SD.Next、ComfyUI PNG 元数据。
- 不迁移旧 HTML 为主 UI；提取 WD14 服务和 ComfyUI 行为。
- 朋友代码在公开发布前保留署名并确认书面授权/许可证。

### 6.3 image-prompt-reverse

- GPL-3.0 Codex Skill，不是本地推理模型。
- 可复用其媒介、主体、构图、镜头、光影、色彩、材质、背景和风格分析框架。
- 转为在线视觉模型的结构化反推提示模板。
- 不替代 WD14；二者分别承担标签和自然语言视觉分析。

### 6.4 xinyueai

- 可参考 Provider 路由、能力管理、健康检查、任务状态、Worker 协议、资产和备份。
- ComfyUI 工作流清单设计值得参考：原始工作流、bindings、outputNodes、参数限制。
- 根项目未确认整体许可证，只有部分目录发现独立许可证。
- 未确认授权前只参考公开架构、接口形态和行为，不复制源码。

## 7. 技术决策（已锁定）

- 主工程始终为 grimoire，保留 Electron + React + TypeScript + Vite + Tailwind + Zustand。
- 数据库从 sql.js 改为原生 SQLite，由主进程独占访问，使用事务、外键、索引、WAL 和迁移版本。
- JSON 仅用于交换，不是内部真相来源。
- 图片默认托管复制并按内容哈希去重；外部项目可链接，也可选择复制。
- 外部链接失效可检测、重新定位；导出可选择收集外部资源。
- WD14 采用 Electron 管理的 Python 辅助进程。
- P0 通信采用随机 127.0.0.1 端口 + 临时高强度令牌。
- Python 不直接修改 SQLite；CPU 必须可用，GPU 可选。
- 应用和模型包分离，支持推荐模型下载与离线导入，校验版本和哈希。
- 保留 OpenAI 兼容供应商，建立 AIProviderAdapter、ImageAnalyzerAdapter、GenerationAdapter。
- P0 只承诺现有供应商、WD14 和 ComfyUI。
- P0 发布 NSIS 安装版和便携目录/ZIP 版。
- GitHub Actions 自动执行类型检查、测试和构建。
- P0 简体中文，但从第一天使用国际化键；英文为 P1。

当前代码已知事实：现有 database.ts 使用 sql.js，最终通过整库 export 和 writeFileSync 落盘；即便执行 WAL PRAGMA，也不具备原生 SQLite WAL 的真实崩溃恢复能力。

| 资源库 | 图片哈希、托管副本、外部链接、缩略图、重新定位和空间统计 |
| 反推中心 | WD14 与在线 AI 识图，保存标签、描述、置信度和来源 |
| ComfyUI | 状态、模型/LoRA、快捷生成、工作流、参数绑定、提交和结果读取 |
| 任务系统 | 队列、状态机、取消、重试、恢复和进度事件 |
| 无限画布 | 复用画布引擎和业务节点，不自行管理数据库、密钥或网络 |
| 历史系统 | 提示词版本、参数、种子、模型、工作流和输入输出关系 |
| 迁移与交换 | 双项目迁移、完整 ZIP、项目包和单项导入导出 |
| 诊断中心 | 结构化日志、状态、错误码、诊断包和脱敏 |

### 8.2 允许依赖

- UI 通过类型化 IPC 调用应用服务。
- 应用服务调用仓储、文件服务、任务系统和外部适配器。
- 工作台与无限画布通过领域对象 ID、命令和事件交换内容。
- WD14 与 ComfyUI 统一接入任务、历史和日志系统。

### 8.3 禁止依赖

- Renderer 直接访问 SQLite、文件系统、Python 端口、ComfyUI 或 API Key。
- 无限画布继续用 IndexedDB 作为数据真相，或自行直连远程 AI。
- React 组件直接拼写 SQL、ComfyUI 节点字段或供应商特殊协议。
- Python 服务直接修改主数据库。
- 工作流分析覆盖、丢弃或破坏原始 JSON。
- 业务模块通过彼此的 Zustand Store 建立隐式耦合。

### 8.4 核心数据流

    新建项目或快速会话
      -> 导入图片（托管复制或外部链接）
      -> 记录哈希和资产元数据
      -> 创建 WD14 / AI 识图任务
      -> 保存反推结果和来源
      -> 编辑、组合、收藏并生成提示词版本
      -> 选择快捷配置或导入 ComfyUI 工作流
      -> 自动分析或手动映射参数
      -> 提交持久化任务
      -> 接收队列、进度、失败或输出
      -> 结果进入资源库、历史和项目
      -> 发送到工作台或无限画布继续创作

### 8.5 错误流

外部服务、数据库、文件和 Python 错误统一转换为版本化错误对象，包含错误码、模块、任务 ID、阶段、是否可重试和恢复建议。任务失败会持久化状态并释放 UI；技术上下文进入脱敏日志。应用重启后，未完成任务标记为“待恢复、外部仍运行或已中断”，不能伪装成成功。

### 8.6 扩展点

- AIProviderAdapter：文本和视觉模型。
- ImageAnalyzerAdapter：WD14、在线视觉模型及未来反推器。
- GenerationAdapter：ComfyUI 及未来生成后端。
- WorkspacePanelDefinition：可切换、分割的业务面板。
- CanvasNodeDefinition：P0 内置节点，P2 沙箱插件。
- Importer/Exporter：按格式和版本注册导入、导出、迁移处理器。
- TaskHandler：统一排队、取消、重试、恢复、进度和日志。

以下格式均必须显式版本化：数据库、IPC、JSON、ZIP、项目包、画布、工作流映射、Python 服务协议和任务状态。

- 同时迁移现有 grimoire 与朋友项目。
- 新库校验记录数量、外键关系、收藏关系、资源哈希和关键字段。

- 迁移必须可重复执行，不得依赖一次性不可追踪状态。

## 10. 安全与隐私规格（已锁定）

- 当前无账户、登录、角色或多人权限；Windows 当前登录用户是本地数据所有者。
- API Key 使用 Windows safeStorage 加密，数据库只保存密文。
- Renderer 只获得 hasKey、掩码和配置状态，主进程负责解密和请求。
- 普通备份不包含 API Key、令牌、认证头、图片正文或完整敏感配置。
- P0 不做 API Key 跨设备导出；换电脑重新填写。
- Renderer 不直接访问数据库、文件系统、Python、ComfyUI 或远程 Provider。
- Preload 只公开细粒度方法，不公开通用文件读取、任意网络请求、命令执行或原始 ipcRenderer。
- IPC 和导入数据用共享 Schema 校验，设置字符串、图片、工作流、批量数和文件大小上限。
- Electron 窗口启用 contextIsolation、sandbox、严格 CSP、导航限制和最小 Preload API。
- 禁止任意页面跳转和任意新窗口；外链验证后交给系统浏览器。
- Python 仅监听随机 127.0.0.1 端口，使用高强度临时令牌。
- ComfyUI 默认本机；远程地址需用户明确配置，导入文件不能静默改变连接地址。
- ComfyUI JSON 只解析和提交，不执行脚本、不安装自定义节点。
- 在线识图前显示目标 Provider 和图片将发送到外部服务；WD14 标记为本地处理。
- ZIP 防路径穿越、绝对路径覆盖、符号链接逃逸、压缩炸弹和同名覆盖。
- 图片做真实格式签名校验，不能只相信扩展名。
- 永久删除、清空回收站和覆盖恢复必须明确确认。
- 第三方代码固定版本、记录仓库、提交、许可证、修改范围和升级说明。

### 10.1 当前代码需要优先修复的安全缺口

审计发现以下旧代码行为不能带入升级版：

1. Provider 列表会将解密后的完整 API Key 返回 Renderer。
2. CSP 仍允许 unsafe-inline 和 unsafe-eval。
3. 全局错误页把异常文本拼接到 innerHTML。
4. Electron 窗口当前配置 sandbox: false。
5. 多个 IPC 使用 any，缺少运行时参数校验。
6. auth_json 和 config_toml 可能承载额外敏感配置。
7. 日志可能包含上游原始错误和潜在敏感信息。
8. 图片当前主要保存外部绝对路径，尚无托管资源库、哈希和失效链接处理。
